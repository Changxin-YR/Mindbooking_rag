# API Foundation

The backend exposes one modular monolith through three API surfaces:

- `/api/v1`
- `/writer/api/v1`
- `/admin/api/v1`

Each surface currently exposes `health/live` and `health/ready`. The unprefixed
`/health/live` and `/health/ready` paths are also available for infrastructure probes.

OpenAPI is generated by FastAPI at `/openapi.json`; interactive documentation is at `/docs`.

Reader discovery, rating, social, growth, correction, and minor-protection endpoints are documented in `reader-experience.yaml`; notification history is exposed by the live FastAPI contract. `GET /api/v1/notifications` requires the account Bearer session, supports `category` filtering, and limits results to 1-100 newest-first records.

Author Finance contract creation uses the staging-only `SANDBOX_CN_2026_V1` policy and returns a deterministic virtual agreement document plus SHA-256. The owning Writer can retrieve it with `GET /writer/api/v1/finance/contracts/{contract_id}`; this is simulation evidence, not a formal legal contract.
Notification records include `is_read`; `GET /api/v1/notifications/unread-count` returns the account-scoped count, and `POST /api/v1/notifications/{notification_id}/read` marks one notification read idempotently.

V1.2 platform governance endpoints are documented in `governance.yaml`, `author-center.yaml`,
`admin-center.yaml`, and `risk-center.yaml`. The live FastAPI contract at `/openapi.json`
remains authoritative for generated clients.

## Sandbox commercial adapters

Staging/Compose can select `PAYMENT_PROVIDER=SANDBOX_ALIPAY` or
`SANDBOX_WECHAT`, and `PAYOUT_PROVIDER=SANDBOX_BANK`. These adapters use the
existing signed callback, idempotency, delayed-callback, duplicate-callback,
and terminal-state contracts without contacting a third-party network.
`SANDBOX` and `SANDBOX_PAYOUT` remain compatibility names.

New contracts default to the versioned virtual policy `SANDBOX_CN_2026_V1`
(author 7000 BPS, withholding 1000 BPS above the 100000-cent threshold). The
policy is persisted as a contract-version snapshot and is explicitly a staging
simulation rather than tax or legal advice.

All errors use the explicit snake_case DTO below:

```json
{
  "error": {
    "code": "RESOURCE_NOT_FOUND",
    "message": "Resource not found",
    "request_id": "REQ_...",
    "trace_id": "TRACE_..."
  }
}
```
