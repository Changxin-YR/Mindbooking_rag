# V1.2 Persistence and Financial Continuation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Continue V1.2 by making the highest-risk runtime paths durable and transactionally safe without changing frozen business rules.

**Architecture:** Keep the existing FastAPI modular monolith and SQLAlchemy/Alembic stack. Add SQL-backed repositories/services behind the current application contracts, and introduce an explicit shared SQLAlchemy connection boundary for payment, recharge, and wallet mutations. Keep in-memory implementations for unit tests and development fallback only.

**Tech Stack:** Python 3.14, FastAPI, SQLAlchemy 2, Alembic, MySQL 8.4, pytest, existing TypeScript clients and Docker Compose.

### Scope gaps checked against the frozen requirements

This continuation does not invent production payment providers, contract share percentages, withdrawal thresholds, tax rules, or identity-provider credentials. Membership/gifts/rewards, full revenue/settlement/withdrawal workflow, Outbox consumers, fine-grained DataScope/MFA, and complete production E2E remain subsequent waves because their required business parameters or runtime contracts are not yet complete.
